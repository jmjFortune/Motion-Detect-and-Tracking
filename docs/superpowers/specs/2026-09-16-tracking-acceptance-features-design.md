# 运动目标跟踪验收功能设计

## 1. 目标与范围

在现有 `ball_camera_track.py` 实体球机跟踪链路上补齐课题验收要求，不重写 YOLO、BoT-SORT、运动分类、目标锁定、卡尔曼预测和 PTZ 控制。新增功能包括：实时状态界面、目标即将越界报警、标注结果录像、性能与误差统计、连续稳定跟踪 10 秒判定、人物居中清晰抓拍，以及不规则运动、光照变化、多目标干扰和短时遮挡的回归与实验报告。

继续使用 OpenCV 窗口，不引入 Qt 等大型 GUI 依赖。程序默认离线仿真不连接球机；只有 `--execute` 才允许 PTZ 输出。`--continuous` 一直运行到 Q、Esc、关闭窗口或 Ctrl+C。

## 2. 验收定义

### 2.1 连续稳定跟踪 10 秒

- 稳定跟踪对象是持久锁定的同一物理目标，不是任意检测框。
- 目标在当前帧有有效检测框时累计连续时间；目标缺失时本次连续计时立即归零。
- BoT-SORT 更换 ID 但通过空间连续性成功重关联时，视为同一物理目标，不重置计时。
- 达到 10 秒后锁存 `stable_tracking_achieved=true`，后续短时丢失不撤销已经达成的结果。
- UI 显示 `STABLE x.x/10.0s`，达标后显示绿色 `PASS`。
- 误差定义为目标框中心相对画面中心的像素误差，分别记录 `error_x_px`、`error_y_px` 和径向误差。

### 2.2 人物居中自动抓拍

- 仅对锁定类别 `person` 生效。
- 目标中心位于配置的水平、垂直中心死区内，且连续满足 3 帧。
- 云台两轴输出都处于零速或静止保持状态，避免转动模糊。
- 原始未标注帧的拉普拉斯清晰度不低于默认阈值 80。
- 每次运行只保存一张 `center-capture.jpg`；保存成功后 UI 显示绿色 `CAPTURE SAVED`。
- 保存动作在运行中立即完成，不依赖程序正常退出。

### 2.3 即将越界报警

- 使用卡尔曼位置和速度预测未来 0.5 秒的目标框。
- 预测框进入画面四周 8% 的危险区即触发报警，方向取 `LEFT`、`RIGHT`、`TOP`、`BOTTOM`，角落可同时包含两个方向。
- 报警表现为红色窗口边框、醒目文字和一次短促提示音；提示音失败不得影响跟踪。
- 每次报警立即向 `events.csv` 写入时间、目标 ID、方向、预测框、当前误差，并保存一张 `alarm-<序号>.jpg` 标注截图。
- 同一方向触发后冷却 3 秒；目标预测框返回安全区后重新布防。不同方向独立处理。
- 没有新鲜目标观测时不依赖纯预测报警，避免目标已经丢失后产生虚假事件。

### 2.4 结果录像

- 实体执行默认录制 `annotated.mp4`，可用 `--no-record` 关闭。
- 视频包含目标框、锁定 ID、预测点与连线、中心准星、轨迹、PTZ 指令、FPS、帧延迟、连续跟踪时间、报警和抓拍状态。
- 使用 OpenCV `VideoWriter` 和 `mp4v`，默认输出帧率 10 FPS；若编码器无法打开，在 UI 和报告中明确标记失败，但不能导致 PTZ 控制失效。
- Q、Esc、关闭窗口、Ctrl+C、异常和看门狗停止路径都必须释放录像文件。

## 3. 架构与模块边界

新增 `tracking/` 包，避免继续扩大 `ball_camera_track.py`：

- `tracking/alarm.py`
  - `BoundaryAlarmConfig` 保存预测时长、危险区比例和冷却时间。
  - `BoundaryAlarm.update(...) -> AlarmEvent | None` 是无 I/O 的状态机，负责方向、冷却和重新布防。
- `tracking/recorder.py`
  - `AnnotatedVideoRecorder` 负责打开、写入、失败状态和幂等关闭录像。
  - 不读取摄像头、不执行检测、不发送 PTZ 指令。
- `tracking/metrics.py`
  - `TrackingMetrics` 负责滚动 FPS、帧龄、连续跟踪时间、丢失次数、报警次数、误差样本和分位数。
  - 以单调时钟计算时延，不把系统时间回拨误判为负延迟。
- `tracking/session.py`
  - `TrackingSession` 创建一次运行目录，持续写入 `events.csv` 和 `tracking-error.csv`，原子保存报告并管理抓拍文件名。
  - 不持有相机或控制器。
- `tracking/overlay.py`
  - `draw_tracking_overlay(...)` 只绘制 UI；输入为帧、检测结果、控制决策和指标快照，返回标注帧。
- `tracking/adaptation.py`
  - `AdaptivePrediction` 根据卡尔曼创新量识别急转弯或速度突变。正常使用 0.1 秒预测；突变时临时缩短为 0，连续稳定后恢复，减少错误超前。
  - `LowLightEnhancer` 根据灰度均值判断低照度，仅在低于阈值时对亮度通道做 CLAHE；同一增强帧同时供检测与 GMC 使用，避免两条视觉链输入不一致。

`ball_camera_track.py` 保留参数解析、资源装配和主循环。它调用上述模块，不复制报警、统计、录像或文件管理逻辑。现有 `ptz/target_tracker.py` 继续负责卡尔曼和二阶 PD/速度前馈控制。

## 4. 数据流

```text
RTSP 最新帧
  → 低照度自适应
  → YOLO + BoT-SORT + GMC + 运动分类
  → 持久目标锁定/ID 重关联
  → 自适应卡尔曼预测
  ├─→ 二阶 PD + 速度前馈 → PTZ 连续速度
  ├─→ 0.5 秒边界预测 → 报警事件/截图
  ├─→ 中心与清晰度判定 → 单张原图抓拍
  ├─→ 指标与误差 CSV → 实时误差曲线/报告
  └─→ UI 叠加 → MP4 录像与显示窗口
```

控制线程继续独立于 YOLO 推理。主循环超过观测超时后发布空观测，控制器立即停止；UI、录像或报警故障不得阻塞看门狗心跳。

## 5. 实时 UI 与核心参数

UI 至少显示：处理 FPS、当前帧龄毫秒、锁定目标 ID/类别、运动或静止状态、卡尔曼预测速度、水平/垂直/径向误差、Pan/Tilt 速度指令、连续稳定时间、边界报警方向、录像状态和抓拍状态。颜色规范：绿色表示已达标或已保存，黄色表示等待，红色表示报警或故障，紫色表示锁定框与预测点。

轨迹只保留最近 50 个目标中心，目标释放后清空，防止无限增长。窗口尺寸变化不改变检测坐标系。

## 6. 适应性要求

- **不规则运动：** 用卡尔曼创新量识别模型失配，突变期间禁用超前预测但继续使用当前检测框控制；恢复稳定后再启用 0.1 秒预测。
- **光照变化：** 记录每帧亮度；低照度才启用 CLAHE，正常光照不改变输入。曝光突变不得制造新的目标 ID 或 PTZ 非零指令。
- **多目标干扰：** 首次只从可靠运动目标获取锁；锁定后其他更大或更快目标不得抢占。
- **短时遮挡：** 缺失时立即停止 PTZ，但保留目标身份 2 秒；同类别、位置和尺度连续的框可重关联。超过 2 秒才释放并允许选择新目标。
- **静止目标：** 进入中心保持滞环后清零速度和内部加速度，避免最小有效速度造成等幅震荡。

## 7. 文件与报告

每次运行创建 `output/ball-track-YYYYMMDD-HHMMSS/`，包含：

- `annotated.mp4`：带 UI 的结果视频；
- `center-capture.jpg`：唯一清晰抓拍；
- `alarm-001.jpg` 等：报警截图；
- `events.csv`：报警和关键状态事件；
- `tracking-error.csv`：逐样本误差；
- `tracking-error.png`：X/Y/径向误差曲线，每 2 秒刷新并在退出时最终刷新；
- `control.csv`、`detections.csv`：现有控制与检测证据；
- `last.jpg`：最后标注帧；
- `report.json`：稳定跟踪、抓拍、报警、录像、FPS、时延、误差分位数、丢失和重关联次数、停止确认及故障。

报告写入临时文件后替换正式文件，避免异常退出留下半截 JSON。凭据、RTSP 密码和 `.env` 内容不得进入任何输出。

## 8. 错误处理与安全

- 录像、提示音、曲线更新和截图失败记录为非致命输出故障，跟踪和安全停止继续工作。
- 相机连接、视频过期、控制请求失败、看门狗触发或机械边界触发属于控制故障，立即发送零速并结束实体执行。
- 所有退出路径依次停止 PTZ、结束控制线程、通知独立看门狗、关闭 RTSP、录像、CSV 和窗口。
- 连续模式只移除运行时长和相对起点行程限制，仍保留设备机械边界、观测超时、命令上限与独立看门狗。
- 不把 ISAPI 指令值宣称为已标定角速度，也不把软件 jerk 限制宣称为电机物理 jerk 保证。

## 9. 测试与实机验收

单元测试覆盖：四方向与角落报警、0.5 秒预测、8%危险区、3 秒冷却与重新布防；录像打开失败和幂等关闭；FPS/帧龄/连续时间与中断重置；单次抓拍；急转弯禁用预测与恢复；低照度启用和正常光照旁路；多目标不抢锁；遮挡停止、ID 重关联和超时释放；静止目标中心保持。

集成测试使用合成帧和假相机，验证 UI/录像故障不阻塞 PTZ 停止，默认离线模式零网络连接，实体模式异常退出仍重复停止。完整回归继续使用 `python -m unittest discover -v`。

实机验收由用户在场、球机周围清场后执行，至少记录以下场景：匀速横移、突然变向、上下运动、静止、两人交叉、短时遮挡、正常光和低照度。验收结果必须包含：同一目标连续有效跟踪至少 10 秒；生成误差曲线；人物居中时只生成一张清晰抓拍；目标预测即将越界时生成方向正确的报警事件和截图；结果 MP4 可播放；停止后球机反馈稳定。

性能报告记录平均与 P95 帧龄、平均处理 FPS、录像成功状态和跳帧数。新增功能在同一输入上的平均处理 FPS 相对关闭录像与 UI 统计的基线下降不得超过 15%；若轻薄本达不到，优先降低录像分辨率或帧率，不降低 PTZ 控制安全等级。
