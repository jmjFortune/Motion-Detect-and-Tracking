# 静止与移动摄像机统一运动目标检测设计

## 目标与边界

在同一流水线内检测、跟踪完整的人、狗、猫，并区分相机造成的画面运动与对象自身运动。相机从静止转为移动时不重载模型、不切换跟踪器、不重新初始化背景模型。

保留现有 `motion_detector.py` 和 `test_motion_detector.py`，不修改其内容。它们仍作为 MOG2 基线版本。

本阶段不发送真实 PTZ 指令，不接入球机账户，不自动打开摄像头进行验收，也不实现自动抓拍。本阶段输出选中目标的 ID、完整框、中心、残余位移及运动状态，供后续控制模块使用。

## 方案取舍

1. **采用：YOLO-Nano + BoT-SORT + 共享光流运动补偿 + 对象运动判定。** 有完整语义框、持续 ID 和预测能力，适合现有代码与轻薄本环境。BoT-SORT 本身不是运动分类器，必须额外判断运动。
2. **不采用：纯光流残差分割。** 计算量较低、类别不限，但容易输出手、皮肤等碎片，不能稳定表达完整人或动物。
3. **不采用：静止时 MOG2、移动时切换跟踪器。** 可作为基线，但有交接、背景恢复和轨迹连续性问题。

## 文件职责

- `camera_motion.py`：背景特征选择、LK 追踪、RANSAC 变换估计、补偿质量与局部运动掩膜。
- `object_motion.py`：按对象 ID 维护运动证据、运动状态、显著性评分和目标锁定。
- `unified_motion_detector.py`：视频输入、YOLO 推理、BoT-SORT 适配、显示与可选 CSV 输出。
- `test_camera_motion.py`、`test_object_motion.py`、`test_unified_motion_detector.py`：合成场景和实际依赖接口的回归测试。
- `README.md`：增加新旧版本运行方式、指标含义和调参说明。

继续使用当前 `pyproject.toml`、`uv.lock` 及 `.venv`。不为本功能新增深度模型或安装额外 ReID 依赖。

## 数据流与共享补偿

每帧仅执行一次 YOLO 推理。YOLO 加载一次，默认 `yolo26n.pt`、输入尺寸 416、CPU 推理，默认类别为 `person,dog,cat`。

直接使用现有 Ultralytics BoT-SORT 实现，并将其 GMC 适配为共享的相机运动估计器。BoT-SORT 更新时调用该估计器一次；对象运动判定复用本次变换和局部残差，不再独立运行第二套背景光流估计。

先让所有被允许的语义对象参与跟踪，再判断其是否运动。不能先过滤静止对象，否则对象停止、被球机跟随或短暂遮挡时容易丢失 ID。

关闭 ReID。框外背景特征用于估计相机运动，对象框内残差用于判定对象自身运动。

## 相机运动估计

图像缩小后提取分布于背景的 Shi-Tomasi 角点，排除语义对象框和图像边缘。通过金字塔 LK 光流追踪前后帧角点，进行前后向一致性检查；排除落入当前对象框的点。

默认使用 `estimateAffinePartial2D` 的 RANSAC 部分仿射变换，描述相邻帧的平移、旋转和一致缩放。这不是完整单应矩阵，不宣称覆盖任意大幅透视变化。优先验证低速、固定变焦的球机运动；完整单应性模型作为后续对比实验，而非本次同时实现两种模型。

质量门槛包括有效背景点数、RANSAC 内点比例、特征分布和变换有限性。变换估计失败时返回供跟踪器使用的单位变换，但运动判定明确输出 `UNKNOWN`，不能把失败冒充相机静止。

将上一帧灰度图变换到当前帧，生成有效重叠区域掩膜。排除新进入视场和插值边缘，抑制背景整体亮度偏移后，计算局部差分掩膜。背景缺乏纹理、严重模糊、快速移动、强视差和局部照明变化仍可能导致误判，界面必须显示补偿质量。

## 对象运动判定

按跟踪 ID 保存前一帧中心和运动证据。仅在前后帧连续可见且补偿可信时计算中心残余位移：

`residual = current_center - transform(previous_center)`

残余速度以像素/秒表示，另给出相对对象框对角线的归一化速度。视频文件使用帧率形成时间轴；实时源使用实际采集时间间隔，而非假定固定推理帧率。

同时统计完整对象框内有效区域的局部运动像素比例。判定证据包括整体残余速度或内部运动量，因此人站立挥手、动物摆动身体部位仍可使整个对象被判为运动。

初始状态为 `UNKNOWN`；运动证据连续确认后进入 `MOVING`。停止阈值低于启动阈值，并要求连续静止证据以降低闪烁。补偿失败期间不累积新的运动或静止证据；短暂保留既有目标状态并显示低可信标记，持续失败则转为 `UNKNOWN`。

显示的 `motion` 是补偿后变化像素比例，不是运动概率；`speed` 是视觉残余速度，不是实际米/秒或云台角速度。

## 显著目标和锁定

只在确认 `MOVING` 的完整语义对象中选择目标。初选综合对象框大小、归一化残余速度、内部运动比例和持续时间，各项归一化后评分。

选中后优先保持同一 ID，不因另一对象突然变大而每帧切换。短暂丢失时保留 ID，界面标为 `LOST`，但不输出旧坐标冒充本帧有效观测。超出丢失宽限或确认停止后重新选择运动对象。

默认仅显示运动对象的完整框：普通运动目标用黄色，选中目标用红色。可通过调试选项显示静止对象、UNKNOWN 对象和局部残差掩膜；局部变化块不是最终目标框。

## 视频与退出

支持摄像头索引、视频文件及 RTSP。支持无窗口模式和最大帧数，以便自动测试。CSV 记录时间、目标 ID、框、运动状态、残余速度和补偿质量。

检测窗口支持 Q、Esc 和窗口关闭按钮退出，统一释放 VideoCapture、输出文件和窗口资源。无法打开视频源、未知类别、模型加载失败时给出清晰错误，不打印含账号密码的完整 RTSP 地址。

## 验证与验收

采用测试驱动开发：每个行为先写失败测试，再实现并运行回归测试。

合成场景覆盖：

- 相机静止、对象静止：没有 MOVING 目标。
- 相机静止、对象整体移动：完整对象被判为 MOVING。
- 背景整体平移、对象随背景移动：补偿后不误判对象运动。
- 背景整体平移、对象相对背景移动：仍能确认 MOVING。
- 对象中心不变但框内局部变化：能够判定整个对象运动。
- 新出现视场边缘：不把无对应历史像素当作对象运动。
- 背景无纹理或有效点不足：输出 UNKNOWN，不产生新运动目标。
- 多对象：显著目标可选择，已锁定 ID 不频繁跳转。
- 遮挡和短暂丢失：不使用过期坐标，不遗留无限增长的历史状态。
- 接口测试确认真实 BoT-SORT 更新能复用共享 GMC；YOLO 本地权重加载和少量无窗口推理可运行。

真实验收需后续通过电脑摄像头或海康球机视频完成：静止、慢速左右/上下转动、挥手、多对象、遮挡。合成测试通过不能等价为真实球机已验证。报告显示真实测得帧率，不预先承诺实时速度。

## 后续双轴控制边界

Pan 和 Tilt 分别控制，轴数不代表控制阶数。后续采用位置/速度估计、PD/PID 误差反馈和速度/加速度/jerk 受限规划；检测与控制分离时钟。软件约束的是命令轨迹，物理平滑程度仍需设备反馈验证。

当前未提供球机型号与接口能力，因此本阶段不实现或测试真实控制。输出像素速度不能直接作为物理角速度前馈，接入时需要视场角或标定信息。
