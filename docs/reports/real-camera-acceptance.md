## 6. 需要人工确认的异常（本报告不掩盖）

有 **9 帧**（839 中的 1.07%）残余归一化速度 > 0.4，最高 id=11 在 t=9.73s 达 355.5 px/s（2.94 个框对角线/秒），且这些帧的：

- `gmc_reliable=1`、`gmc_reason=ok`（**不是补偿失败造成的**）；
- `motion_ratio` 极低（0.004–0.05，即框内几乎没有局部变化）；
- 相邻同 ID 帧的中心位移都 < 60 px（已逐帧算过，没有突跳）。

「中心动得快 + 框内几乎不变」有两种可能：真实的人快速走动/快速穿过画面（球机视场窄时远景可能被放大），或跟踪器 ID 关联瞬间偏移造成的假速度。**本报告无法区分**：本次运行的 `--headless` 没有保存逐帧原始画面，而当前会话的模型不支持读取图像，我无法看 `best.jpg` 判定。

建议下一步（按代价从低到高）：

1. 重跑一次带窗口的 `ball_camera_detect.py --show-all --duration 30`，让人在画面里明显走动，人工确认那些高速度帧的框是否贴着人；
2. 或在 `--show-all` 下加 `--max-frames` 复现同一时段，保存原始帧序列后离线比对；
3. 若确认是 ID 关联抖动，考虑在 `update_tracks` 里丢弃「同一 ID 相邻帧中心位移超过框对角线若干倍」的观测，而不是让它直接进入速度/确认链。
